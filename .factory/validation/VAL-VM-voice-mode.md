# Voice Mode — Validation Contract Assertions

### VAL-VM-001: Voice mode activation from chat screen
Tapping the microphone button on the AI chat input bar opens a full-screen voice mode modal. The modal covers the entire screen with a dark/themed background and displays the animated orb in idle state.
Evidence: screenshot of voice mode modal open with orb visible; assert modal is full-screen.

### VAL-VM-002: Voice mode idle state visual
When voice mode opens, the orb is in idle state (static or subtly pulsing). A "Tap to speak" label or equivalent prompt is visible. Close button is accessible.
Evidence: screenshot showing idle orb, prompt text, close button.

### VAL-VM-003: Listening state — tap to start recording
Tapping the orb or mic button in voice mode starts audio recording via expo-audio. The orb transitions to a listening animation (pulsing/expanding). A "Listening..." label appears.
Evidence: screenshot of listening state with pulsing orb; assert audio recorder is active.

### VAL-VM-004: Listening state — audio recording
While in listening state, expo-audio records audio (WAV 16kHz mono on iOS, AAC on Android). The recording captures the user's speech for sending to the backend STT.
Evidence: audio file created in cache directory; file size > 0 bytes; correct format per platform.

### VAL-VM-005: Speech end detection and auto-stop
After the user stops speaking, the voice mode automatically detects silence (via speech recognition end event or timeout) and stops recording. The transition to processing state is automatic without user intervention.
Evidence: recording stops automatically after ~2 seconds of silence; state transitions from listening to processing.

### VAL-VM-006: Manual stop recording
User can tap the orb/stop button during listening to manually stop recording. Recording stops immediately and transitions to processing state.
Evidence: tap stop during recording → recording stops, processing state begins.

### VAL-VM-007: Processing state visual feedback
After recording stops, the orb transitions to a processing/thinking animation (different from listening). A "Thinking..." or equivalent label appears. The user cannot start a new recording during this state.
Evidence: screenshot of processing state with distinct animation; mic button disabled.

### VAL-VM-008: STT — auto language detection
Audio sent to the backend uses Sarvam Saaras v3 with auto language detection. The user does NOT need to select a language before speaking. Hindi, Marathi, English, and code-mixed speech (Hinglish) are all correctly transcribed.
Evidence: backend trace showing Sarvam Saaras v3 call; transcript matches spoken content regardless of language.

### VAL-VM-009: STT — transcript displayed in voice mode
After STT completes, the user's transcribed text appears in the voice mode conversation view. The transcript is visible before the AI response arrives.
Evidence: transcript text rendered in voice mode message area; visible during processing state.

### VAL-VM-010: Speaking state — TTS playback with visual feedback
When the AI response arrives with audio (Sarvam Bulbul v3 TTS), the orb transitions to a speaking animation (waveform or rhythmic pulsing). The audio plays through the device speaker. The assistant's text response is also displayed.
Evidence: screenshot of speaking state with waveform animation; audio plays audibly; text response visible.

### VAL-VM-011: Speaking state — Sarvam TTS native voices
TTS audio is generated by Sarvam Bulbul v3 with locale-appropriate native voices. Hindi responses use Hindi speaker, Marathi responses use Marathi speaker.
Evidence: backend trace showing Bulbul v3 TTS call with correct locale speaker; audio sounds natural in the target language.

### VAL-VM-012: Auto-listen after response
After TTS playback completes, voice mode automatically returns to listening state for continuous hands-free conversation. The user can speak their next question without tapping.
Evidence: after audio playback ends, state transitions to listening; recording starts automatically.

### VAL-VM-013: Voice mode dismissal via close button
A close/X button is accessible during any voice mode state (idle, listening, processing, speaking). Tapping it dismisses the voice mode modal and returns to the text chat screen. Any in-progress recording is stopped.
Evidence: tap close → modal dismissed; if recording was active, it stops; text chat screen visible.

### VAL-VM-014: Voice mode dismissal via swipe down
Swiping down on the voice mode modal dismisses it, returning to the text chat. This gesture works from any state.
Evidence: swipe down → modal dismissed; text chat visible.

### VAL-VM-015: Interruption — tap while AI is speaking
If the user taps the orb while the AI is speaking (TTS playing), playback stops immediately and voice mode transitions to listening state. The user can immediately start speaking.
Evidence: tap during TTS playback → audio stops; state transitions to listening; recording begins.

### VAL-VM-016: Error state — STT failure
If STT fails (both Sarvam and fallback), voice mode displays an error message (e.g., "Could not understand audio. Please try again."). The orb shows an error state. The user can tap to try again.
Evidence: screenshot of error state with error message; retry functionality works.

### VAL-VM-017: Error state — network failure
If the network request fails during voice flow, voice mode displays a network error message. The user can retry. No crash occurs.
Evidence: screenshot of network error in voice mode; retry button functional.

### VAL-VM-018: Error state — no microphone permission
If microphone permission is not granted, tapping the voice mode button shows a permission request or an informative error guiding the user to settings. Voice mode does not open in a broken state.
Evidence: assert permission check before opening voice mode; informative error shown if denied.

### VAL-VM-019: Conversation thread visible in voice mode
Voice mode displays a scrollable thread of the conversation (user transcripts and AI responses in text). This allows the user to review what was said during the voice session.
Evidence: screenshot of voice mode showing multiple turns of conversation; thread is scrollable.

### VAL-VM-020: Voice mode messages persist to conversation
Messages exchanged in voice mode are persisted to the same conversation as text chat messages. When voice mode is closed, the messages appear in the text chat message list.
Evidence: exchange messages in voice mode → close voice mode → text chat shows the same messages.

### VAL-VM-021: iOS compatibility — recording format
On iOS, voice mode records audio in WAV format (16kHz mono) using expo-audio. The recording is compatible with Sarvam STT requirements.
Evidence: on iOS device, recording produces WAV file; Sarvam STT accepts and transcribes it.

### VAL-VM-022: Android compatibility — recording format
On Android, voice mode records audio in a format compatible with both Sarvam STT and OpenAI Whisper (AAC/M4A with fallback handling). Recording works without crashes.
Evidence: on Android device, recording produces audio file; backend processes it (via Sarvam or Whisper fallback).

### VAL-VM-023: Voice mode respects theme
The voice mode modal renders correctly in both light and dark themes. Background, orb colors, text colors, and control buttons all use M3 theme tokens.
Evidence: screenshots of voice mode in light and dark theme; colors consistent with M3 scheme.

### VAL-VM-024: Voice mode orb animation performance
The orb animation runs smoothly at 60fps without dropped frames on both iOS and Android. No jank or stuttering during state transitions (idle→listening→processing→speaking).
Evidence: animation runs without visible jank; FPS counter shows consistent 60fps during transitions.

### VAL-VM-025: Haptic feedback on voice mode interactions
Tapping the orb to start/stop recording triggers haptic feedback (light impact). This provides tactile confirmation of the action.
Evidence: haptic feedback felt on tap; `expo-haptics` impactAsync called.
