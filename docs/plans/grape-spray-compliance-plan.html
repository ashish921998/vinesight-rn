Executive summary

The review confirmed the plan's foundation and then made it honest: the slice fixes a real safety bug, but its visible outcome and its value both hinge on backfilling existing data.

Product principle
Validate the pilot, not the engine. Fix the safety bug, ship the export, backfill the data.

The validated goal is a paid pilot for central record-keeping + audit export. Scope was cut to match that, not a full compliance engine on an unproven bet.

The measured reality

A read-only query against production made the stakes concrete and reshaped the plan.

99%sprays with no safe-harvest date
97%farms that flip to "unverified"

Consequence: the fail-closed fix needs a self-explaining card state, and the evaluator + export return "unverified" for ~99% of history until the backfill runs. Backfill is the work.

Preserve

chemical_* tables, legacy PHI rules, the direct-insert farmer write path, and historical spray records all stay valid.

Extend

Additive claim/source/MRL tables, a read-only evaluator that composes phi-service, a real PostHog flag, and compliance fields in the existing export.

Defer

Authoritative write-path RPC (Unit 4), farmer UX (Unit 5), professional workflow (Unit 6), and annual governance (Unit 7) wait for the pilot.

Slice scope

What ships now, what waits. Deferred units are tracked, not dropped.

In scope

  • Fail-closed harvest fix + regression test + self-explaining card state (measured first).
  • Unit 1 (trimmed): claim/source/MRL tables + component link + mix-uniqueness change. Snapshot column deferred.
  • Unit 2 + 2b: light Annexure import + backfill 1,899 existing sprays to claims.
  • Unit 3: read-only evaluator composing phi-service, offline-aware, behind a real flag, catalog via one RPC/view.
  • Unit 3b: compliance fields in the existing audit export.
  • Infra: a PostHog isFeatureEnabled wrapper.

Deferred (not dropped)

  • Unit 4 — authoritative write-path RPC re-architecture (farmer path is a direct insert today; offline implications).
  • Unit 5 — farmer decision-support UX.
  • Unit 6 — professional compliance workflow.
  • Unit 7 — annual governance / runbooks.
  • pgTAP harness — verify via Jest + manual apply instead.

Safe-harvest card · six states

The plan named four; the real state machine is six. Each carries an icon + word label (never colour alone). Unverified is calm amber, never red.

Verified

"Safe to harvest from 15 Mar 2026" + governing PHI. Green/primary.

Not yet verified

~97% of farms. Amber caution token, informational, no dead-end CTA — the farmer can't map sprays this slice.

PHI conflict

Target harvest before governing PHI. Red error. Existing state, KEPT — dropping it would be a safety regression.

Offline

"Can't check — you're offline." Distinct grey, so a connectivity blip never reads as a compliance failure.

No sprays

"No sprays logged yet this season." Reuse the shipped EmptyState.

Loading

Skeleton, not a blank flash — matters on slow rural signal.

Add a dark-aware semantic caution token (modeled like error); export uses neutral "Verified / Pending mapping" labels + an honest header summary so 97%-unmapped reads as in-progress, not non-compliant.

Sliced data flow

A versioned evidence chain feeds one read-only evaluator that composes existing PHI math, behind a real flag, into the card and the export.

Review decisions

12 engineering + 3 design decisions, resolved interactively. These are the boundaries implementation should hold.

ARCH-1Measure, then ship the flip with reason.97% of farms flip to "unverified." Ship the fail-closed fix with a self-explaining card, not a bare flip.
ARCH-2Reuse Jest + manual apply.No pgTAP harness exists; don't spend an innovation token standing one up for the slice.
ARCH-3Defer the snapshot column.Nothing writes it until Unit 4; don't land a dormant column whose shape isn't settled.
ARCH-4Evaluator composes phi-service.One source of PHI math — no second engine to drift.
CQ-1Tri/quad-state return contract.Extend the aggregate to a status field; update callers incl. the missed use-phi.ts edit site.
CQ-2Strictest verified PHI rule.Dedup picks max phi_days among verified+effective rules — fail to the safe side.
PERF-1One RPC/view for catalog.Collapse 5 serial round-trips to 1 — de-risks rural connectivity.
OV-1Wire real PostHog flags.No runtime flag exists today; the slice needs a kill switch + canary for the 97% flip.
OV-2Add the audit export.The export is the pilot's deliverable and already ships — extend it, don't ignore it.
OV-3Add an explicit backfill unit.Mapping 1,899 sprays is the load-bearing work behind the success metric.
OV-4Offline ≠ unverified.A cache-evicted/offline read must say "can't check," never silently render every farm unverified.
DESIGN-1Six card states, fully spec'd.Keep the red conflict state; add loading. Empty states are features.
DESIGN-2Add a caution token.Dark-aware semantic amber for "unverified" — M3 has no warning role and hex is banned.
DESIGN-3Honest export labeling."Verified / Pending mapping" + a true-ratio summary so the auditor reads in-progress, not broken.

Success criteria

Measure decision integrity and coverage — not more spraying.

  • Safe-harvest status never shows "safe" when any in-season spray is unmapped/unverified.
  • The 97% flip ships with a self-explaining state and a real kill switch behind it.
  • Backfill moves the verified-claim coverage from ~1% upward, with a coverage report.
  • The audit export reflects the same verdict the card shows, framed honestly for a buyer/APEDA.
  • Offline never masquerades as a compliance failure.
  • Every new card state reads without colour (icon + label) and meets ≥4.5:1 contrast in en/hi/mr.
