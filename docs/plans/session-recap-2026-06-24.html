We fixed a harvest-safety bug and shipped it

You asked me to review a plan. We reviewed it, found a real safety bug, measured how bad it was, fixed it, and opened a pull request. Here's the whole story in plain terms.

2 reviews run 15 decisions 2 commits 863 tests green PR #177 open
In one sentence: the app could tell a farmer "safe to harvest on this date" even when it had no idea about some of their sprays. We made it say "not sure yet" instead, and shipped that fix. The bigger compliance feature was scoped down and the heavy parts deferred until they're actually needed.

The bug, in plain words

Before

A farm's "safe to harvest" date was calculated by looking only at sprays the app understood. Any spray it couldn't read (no safety date) was silently ignored. So one understood spray + one unknown spray = a confident green "safe" date, hiding the unknown one.

After

If even one spray can't be verified, the app now says "Harvest safety not yet verified — N sprays not yet mapped" instead of a fake safe date. It only shows green when everything checks out. Failing toward caution, not false confidence.

Why it mattered — we measured it

Before fixing, we ran one read-only query against the real database to size the blast radius. The numbers reshaped the whole plan.

99%of sprays (1,899 of 1,916) had no safety date
97%of farms (64 of 66) were at risk of a false "safe"
1spray was actually verified today

Because nearly every farm is affected, the fix had to explain itself calmly (not look like the app broke), and the real value of the bigger feature depends on backfilling that old data — not on fancy logic.

Built the fix

Rewrote the harvest calculation to fail safe, added tests for it, created a calm amber "not yet verified" banner on the farm screen, and a new color token for it.

Handled the offline case

The four farm-screen states now

Verified

"Safe to harvest from 15 Mar" — only when every spray checks out.

Not yet verified

Calm amber, the common case. "N sprays not yet mapped." No false safe date.

PHI conflict

The existing red "don't harvest yet" warning — kept, not broken.

Can't check

Offline / load failed. "Tap to retry." Never reads as "all clear."

What we deliberately did NOT build yet

The plan's heavier half was scoped out — it needs real data prep and is a separate workstream.

  • The versioned label-claim database schema (Unit 1)
  • Importing the ICAR-NRCG Annexure data + mapping the 1,899 old sprays (the real, high-effort work)
  • The shared compliance evaluator and a single fast catalog query
  • Compliance fields in the audit export (the actual pilot deliverable)
  • A real feature-flag kill switch and the catalog "strictest PHI" fix

Honest caveats

  • The Hindi/Marathi wording on the new banners is my best effort — it wants a native-speaker review.
  • A true offline signal needs a native library (and an app-store build); we used the dependency-free version for now and deferred the real one.
  • An old SafeHarvestCard component is tested but unused; the farm screen uses inline banners. Cleaning that up is deferred.
