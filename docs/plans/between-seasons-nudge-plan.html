Between-Seasons Soft Nudge — Implementation Plan

Make "no active season" consistently non-blocking across every logging entry point, instead of the current mix of one stale hard gate and ~10 silent bypasses — without repeating the DB-level incident that made this permissive in the first place. Also close the companion discoverability gap: a between-seasons farm is currently almost invisible on its own detail screen, with "Start Season" buried in an overflow menu.

Why this, why now

The instinct to require an active season before logging anything was already tried — at the database level, in assign_season_id_for_row(), the trigger that runs on every insert/update across all 11 activity tables. Its own source comment explains what happened:

"Permissive for all writes: when no season window covers this date, leave season_id null rather than raising. Previously INSERT raised P0001, which surfaced as a 400 and blocked the write. Recompute / 'start season' backfills the season_id afterwards." assign_season_id_for_row() — production DB, project ibczxoiaonssyzsybebu

That's exactly the branch this work sits on top of (fix/permissive-season-id-insert). Meanwhile the client still has a leftover echo of the old strict era: handleAddActivity in app/farm/[id].tsx blocks with a Cancel/Start-Season alert — but only on the farm-detail screen's primary FAB. Every other entry point bypasses it entirely.

Approach

Nudge, never block. Instead of intercepting navigation at every one of the ~10 call sites (fragile — the next new entry point silently reintroduces the gap), place a single non-blocking banner inside each destination form, where the farm is already known. Almost every entry point already funnels into one of four forms.

C7 — Season Strip empty statetodo

app/farm/[id].tsx:1452-1621 ("Season Strip Card")

The Season Strip — a prominent progress card (pruning date, days elapsed, target harvest) at the very top of the farm screen — only renders when activeSeasonRecord && seasonProgressPct !== null. When a farm is between seasons, the block is skipped entirely and the screen jumps straight to "Vital Signs," with nothing in its place. Fix: render an empty-state card in the same slot when there's no active season — "No active season — Start Season" as its own tappable card (reusing openStartSeasonForm), matching the visual weight the progress card gives to the active state instead of relying on the user to find the overflow menu. This is the season-management-side companion to C1/C2 above (which address the logging-side gap) — same root cause, different symptom: a between-seasons farm is currently almost invisible on its own detail screen.

C8 — A3 (already tracked): unassigned-records notice in reportspending, separate task

cross-reference — not new scope, the recovery-side sibling of this work

A soft nudge only prevents new unassigned records going forward; it doesn't surface the ones that already exist. Sequencing this after C1-C6 makes sense: no point pointing users at a reports notice for a workflow that's simultaneously about to nudge them out of causing more of the same gap.

Non-goals

  • No changes to assign_season_id_for_row() or any DB trigger/constraint — the permissive behavior stays exactly as-is.
  • No blocking dialogs anywhere, including the delegated/consultant RPC path — a consultant should never be prevented from logging for a farmer because that farmer forgot to start a season.
  • No change to resolveOrCreateSeasonIdForDate / resolveSeasonIdForDate resolution semantics.
  • Not unifying the lazy-bootstrap-vs-plain-null split between record types (flagged in the original scoping pass) — separate cleanup, out of scope here.

Open questions

Should the delegated/consultant banner differ in copy from the farmer-facing one?

A consultant managing many farms may see this banner often and for farms they don't directly control the season-starting cadence for. Worth a lighter-weight treatment (e.g. a small inline note rather than a full banner) if it turns out to be noisy in practice — flag for design review rather than deciding upfront.

Does the banner need a per-farm dismiss state, or does it just reappear every time?

Leaning toward "just show it whenever true" (no dismiss/snooze state) since it's informational and cheap to ignore — but worth confirming it doesn't feel naggy once it's live on the highest-traffic form (EntryForm).
